# Home Service Toolkit Run

## Project

Home Service Toolkit Run is a deterministic MuJoCo mission for a humanoid field
robot. The robot navigates to a marked pickup pad, lifts a tool kit, carries it
along a route, and places it on an urgent-job-site pad. The scenario is designed
for home-service logistics, where a reliable handoff matters more than a
showcase walk.

## Robot and task

- Robot: FF Futurist humanoid from the starter asset package
- Embodiment: bipedal humanoid with articulated arms and hands
- Task: pickup, carry, and delivery over one long-horizon route
- Control: deterministic autonomous gait with staged pickup and placement
- Physics: MuJoCo MJCF/URDF compilation, contacts, joints, free-joint payload,
  lighting, camera, and rendered telemetry

The payload is intentionally represented as a free-joint body in the MuJoCo
scene. Its trajectory is logged at the same cadence as the robot base so the
handoff can be inspected without relying on a video-only claim.

## Run

From the repository root:

```bash
python3 -m pip install -r requirements.txt
python3 submissions/home_service_toolkit/run_home_service.py
```

Outputs are written to `submissions/home_service_toolkit/outputs/`:

- `home_service_demo.mp4` — a short demo generated by the submitted code
- `trajectory.json` — sampled robot and payload positions
- `mission.json` — pickup, carry, and delivery milestones

For a quick smoke test:

```bash
python3 submissions/home_service_toolkit/run_home_service.py \
  --headless --duration 2 --fps 8
```

The headless mode validates the MuJoCo model, payload, controller phases, and
telemetry without requiring a local graphics context. For the required rendered
demo, run the default command on a machine with MuJoCo's supported OpenGL
context; the script then writes `home_service_demo.mp4`.

## Highlights

- A clear real-world home-service scenario rather than a free-running animation
- Long-horizon state changes: pickup, carry, and delivery
- Reproducible controller and seeded scene layout
- Explicit mission telemetry plus a rendered demo
- Uses the existing Futurist model and scene assets without external downloads

## Limitations and next steps

The current controller is deterministic and open-loop, so it is a reproducible
mission demonstration rather than a learned policy. A next iteration would add
contact-based grasp verification, obstacle rerouting, a failure injector, and
teleoperation for collecting recovery trajectories.
